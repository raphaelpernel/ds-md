02 · Comment

Le design pilote directement le code

  • Claude Code comme partenaire de code, pas réservé aux ingénieurs : utilisable directement par le design pour construire de vrais écrans
  • gstack structure le travail avant, pendant et après : cadrer une idée, challenger un parti pris, fiabiliser avant de livrer
  • Un cadrage systématique avant de coder (brief, table de décision du design system), pas du code jetable sans garde-fou

03 · Idée

Et si la couleur n'était plus écrite en dur ?

Ajouter au panier data-brand="marmiton"
Ajouter au panier data-brand="coursesu"
Ajouter au panier data-brand="neutral"
  • Le même bouton, la même carte, écrits une seule fois, mais leur couleur est une variable, pas une valeur
  • Cette variable change selon un seul attribut posé sur la page (data-brand="marmiton"), jamais dans le composant lui-même
  • Le composant ne connaît jamais la marque : il lit un alias (« couleur d'action principale »), qui pointe vers la bonne valeur selon l'attribut actif
  • Changer de thème (marque, ou même mode clair/sombre) devient un attribut à poser, pas un nouveau design à produire

04 · Solution

design-system
le langage commun

couleur de marque → alias sémantique → composant
  • Un seul package que toutes les applications importent, jamais l'inverse
  • 32 composants déjà résolus une fois pour toutes : carte recette, en-tête, navigation, boutons, alertes…
  • Trois identités branchées aujourd'hui : neutral (bleu, défaut), marmiton (corail), coursesu (teal), plus un partenaire : carrefour
  • Une doc dédiée dit quoi utiliser, pas juste ce qui existe (Badge vs ChipTag, Modal vs Drawer), pour que personne ne redevine à chaque écran

  • Six applications tournent aujourd'hui sur les mêmes briques : StoreHeader, BottomNav, RecipeCard, Button…

  • Une seule source de vérité pour l'interface ; chaque appli n'ajoute que sa propre logique métier

07 · Stack technique

Une stack simple, pensée pour itérer vite

Next.js React TypeScript Tailwind CSS v4 Style Dictionary Storybook pnpm workspaces
  • Tailwind CSS v4 consomme directement les tokens du design system : pas de valeur dupliquée
  • Style Dictionary synchronise les couleurs automatiquement depuis Figma
  • Storybook documente chaque composant, variante par variante
  • pnpm workspaces relie toutes les applications en un seul monorepo
